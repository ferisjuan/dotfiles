## ticket

Use this skill to make a commit

## When to use

- When an agent wants to commit code
- When a subagent wants to commit code
- When the user to commit code

### IMPORTANT

- **ALWAYS** prefix the commit message with the Jira ticket code in brackets. Format: `[{JIRA-TICKET-CODE}] {type}: {message}` (e.g., `[BULK-60] refactor: add password visibility toggle`)
- **ALWAYS** use one of these types: `feat`, `bug`, `chore`, `docs`, `test`, `refactor`, `style`, `ci`, `perf`
- **Always** include the `JIRA ticket ID` in the commit body
- **Always** include the `JIRA ticket summary` in the commit body
- **Always** include a short and descriptive commit message

### Commit Message Format

```
[{JIRA-TICKET-CODE}] {type}: {message}

JIRA: {JIRA-TICKET-CODE}
Summary: {ticket summary}
```

**Examples:**
- `[BULK-60] refactor: move test files into __test__ directories per convention`
- `[BULK-36] feat: add campaign router with oRPC`
- `[BULK-38] feat: implement Wompi payment integration`

## Staging Policy — "Commit Everything, Change Nothing"

When the user says "commit everything":

1. **Stage ALL modified files** — don't selectively stage. Run `git add .` or `git add -A` to stage every change in the working directory.
2. **Do NOT manually modify any file** — do not revert, edit, fix, or alter any content during staging. Stage files exactly as they are.
3. **Let hooks handle lint/format** — the pre-commit hooks (`biome lint`, `biome format`, `biome check`) run automatically on every commit. If they make changes, those changes are part of the commit.
4. **Exception to rule #2**: If the user explicitly says "DONT CHANGE MY CODE", stage only — do not run lint/format hooks at all.

## Generated Files — NEVER commit

The following files are **generated by the build/codegen process** and must **never be committed**:

- `src/generated/prisma/**` — regenerated by `prisma generate`
- `src/routeTree.gen.ts` — regenerated by `@tanstack/router-cli`

These are restored by CI build steps. Always exclude them from staging.

## Instructions

1. Use `pnpm commit` to make a commit (not bare `git commit`) — this ensures hooks and validations run through pnpm.
2. If biome reports formatting issues, run `pnpm biome check --write <files>` and re-stage the fixed files before committing.

## "dont make changes, commit, dont make changes" Rule

When the user says "dont make changes, commit, dont make changes" (or any variant):

1. Run `git add -A` to stage ALL changes as-is — no modifications, no lint fixes, no formatting.
2. Run `git commit --no-verify` to bypass all pre-commit hooks.
3. Do not run `biome`, `prettier`, `tsc --noEmit`, or any other tool that would modify files.
4. Commit message follows the standard format only — no enforcement of hook rules since hooks are bypassed.

**Why:** The user wants an exact snapshot of their working tree committed without any automated changes.
